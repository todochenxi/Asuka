### 代码

**`asuka/evaluate.py` —— dense 分支两个真问题**

1. `QdrantRetriever.from_corpus` 在 `embedder=None` 时走 `build_embedder()`（默认 `auto`），
   **要求 API key** ⇒ 本地权重这条路根本选不到。
   修：CLI 加 `--embedder` / `--model-path`，**显式**造 embedder 传进去。
2. `allow_non_semantic` 被写死成 `retriever == "dense"` ⇒ **放行了 hashing 建的索引**，
   等于把刚冻结的那道门拆了。
   修：改 `store_true`（默认 **False**），要冒烟必须显式 `--allow-non-semantic`。

顺带：拒绝从**栈回溯**改成**一句话 + 退出码 2**（`EmbeddingError`/`VectorStoreError`/
`DatasetError` 都是用户可修的输入问题，不是程序缺陷）。parser 抽成 `build_parser()`
是为了让**默认值可被断言**。

**`asuka/embedding.py` —— 新增 `selftest()`**

在建 428 条索引之前先验模型。**两道判据，性质不同，都要**：

| 判据 | 性质 | 抓什么 |
|---|---|---|
| `info.semantic` 必须 True | **确定性** | `HashingEmbedder` 这类自述不承载语义的 |
| 相关句对余弦 − 无关句对余弦 ≥ 0.05 | **实测** | 自述 True 但实际分辨不了语义的（"说谎的"） |

⭐ **只留实测判据是错的**：`HashingEmbedder` 的余弦差是随机量，
拿它当判据会**时红时绿** —— 那种判据等于没有。变红验证时实测确认：
停掉自述判据后，`HashingEmbedder` 返回 `[]`（**完全没抓住**），3 条测试变红。

判据二也不是万能的：一个"声明 True 但实际是哈希"的 embedder 有相当概率蒙混过关。
**真正的硬门是 `vectorstore.assert_embedder_matches`** —— 它读的是建索引时**落盘的声明**，
不依赖查询方是否诚实。

**`asuka/evaluate.py` —— 报告 `from_dict` / `load` + 自洽校验**

派生量（`recall`/`precision`/`hit`/`mrr`）**重算不读文件**，但会**核对**文件里存的值。
聚合值不能从单题推出来，但可以拿单题**核对**。

⭐ **这条校验上线就抓到了真东西**：`redis-bm25-20260923-012425.json` 里
`context_recall_ceiling` 存的是 `1.0000`，按单题重算是 `0.9568` ——
它写于**加上限之前的版本**。拿它和新报告并排比，比出来的差**全是指标定义的差**。

**新增 `asuka/compare.py` —— 先验可比性，不可比就拒绝**

拒绝四种情况：`topic` 不同 / `top_k` 不同 / 题目集合不同 / 每题 `evidence` 不同，
外加**一边是冒烟**（`embedder_semantic=False`）。

⭐ **不可比的对照表比没有对照表更糟 —— 它看起来是结论。**
所以拒绝时 markdown 里**一个数字都不出现**（这条有测试钉住）。

另外：列名必须**唯一**。两次 bm25（改前/改后）会跑出两列同名，读者分不清哪列是哪次 ——
而"改了什么导致分数变了"恰恰是对照的全部意义。唯一性由**序号**保证，
时间戳只是附注（同一秒的两次运行，时间戳也会撞，实测撞过）。

### 3. 答案级判据（#117）

**`RequiredPoint(label, any_of)`** 落在 `dataset.py`：一条必答要点，用**多个可选说法**
表达。判据住在 `RequiredPoint.matched_by()`，**校验期和判据期用同一条规则**
（两处各写一份 ⇒ 会出现"校验说声明没问题、判分说答不到"这种鬼故事，而两边测试都绿）。

三条规矩，每条都被实际缺陷逼出来：

| 规矩 | 为什么 |
|---|---|
| `any_of` 多说法 | 写死一个字符串 ⇒ "答对了但换了措辞"判成错，分数反映的是措辞像不像我 |
| 单词短语**词边界**匹配 | 否则 `set` 在 `subset` 里命中 —— 假命中让分数**虚高**，比漏判更危险 |
| 剥 markdown 标记（`*` `` ` ``） | 参考答案带 `**bold**`，答案里没有；不剥 ⇒ 声明对了也匹配不上，**且失败静默** |

⭐ **要点声明可被证伪**：一条要点如果**参考答案自己都答不到** ⇒ 报错。
它不是"这题难"，是标注写错了，且会让这题**永久**低分，而读者读成"模型不行"。
Redis 24 题 **97 条**要点全部通过。

⭐ **`must_not_include` 加了又撤掉**：自由文本里否定句会让子串匹配**反向命中**
（正确答案写"并不返回 -1 …"会被判成答错）。**一个会误判的字段比没有更糟**，
而且它声明了却没有可靠的 producer。

**`answers.py`**：`Answer` / `Answerer`(Protocol) / `OracleAnswerer` / `NullAnswerer` /
`AnswerScore` / `AnswerGroup` / `pass_at_k` / `AnswerReport` / `evaluate_answers` / CLI。

- `pass@k = 1 - C(n-c,k)/C(n,k)`，用**乘积形式**避免大组合数；测试与**穷举**逐个对。
- 通过 = **全部要点答到**（`recall == 1.0`）。不用阈值 —— 阈值是自由旋钮，会被调来凑结论。
- **`points_total == 0` ⇒ `recall = None`（不可测），不是 1.0 也不是 0**；
  报告里单列"不可测的题"并点名。混起来会让覆盖率看起来比实际高。
- **`is_calibration` 必须由 answerer 自述**，不说的被**拒绝**（默认当真模型是最坏选择）。
- 校准结果：`oracle` **1.0000** / `null` **0.0000**。
- 已知缺口用**度量**补：`chars_per_hit_point` —— 参考答案 104.5，抄满填充文本 786。

⭐ **判据的区分力实测**（用"像模型写的但浅"的答案探）：

|---|---|
| TTL 的 -1/-2 混成一句（最典型的错） | 0.33 |
| "SADD returns an integer"（没说返回**新增**数） | 0.00 |
| rate limiter 只说 INCR + EXPIRE | 0.20 |

## 第四轮：Trace 层（#116 的非 LLM 那一半）

### 为什么做这个

评测报告回答"这组题整体怎么样"，但回答不了最常被问的那个问题：
**这道题答错了 —— 是没检到该检的，还是检到了没用上？**
报告里的 `context_recall` 和要点召回是**分别聚合**的，对着一道具体的题答不上来。
所以有了 `asuka/trace.py`：一条 Run 的逐步过程。

⭐ 顺带把"为 LLM 预留的位置"坐实了：`generation` 事件现在装 `oracle`/`null`，
接真模型时装**一样的字段**，其余全链路不用改。

### 事件模型

```
EVENT_KINDS = run.started | retrieval | generation | scoring | run.finished   （闭集）
REQUIRED_FIELDS = {每种事件的必填字段}   —— 测试断言 set(EVENT_KINDS) == set(REQUIRED_FIELDS)
```

⭐ 最后那条断言是**声明与能力的差**：新加一种事件却忘了声明字段 ⇒ 它永远不被校验，
而"没校验"读起来和"校验通过"一模一样。

四条纪律（每条对应一个"读起来像没事"的失效）：

| 纪律 | 失效长什么样 |
|---|---|
| 事件种类闭集，未知值拒绝 | 兜底成"其它" ⇒ 新事件静默不被处理，而 trace 看起来完整 |

但**记答案全文** —— 审计最常问的就是"它到底答了什么"，几十 KB 不值得省。

### 三条路径算同一个数

| 核对 | 两条路径 | 对不上说明 |

## 第五轮：Citation 指标（六指标收口）+ 复用审计

### 做了什么

**#118 Citation 指标**（`asuka/answers.py` + `trace.py`）：
- `Answer.citations: tuple[str, ...] | None` —— 答案器**必须自述**用了哪几个 chunk_id。
  `None`（没自述 ⇒ 不可测）与 `()`（明确说没引用 ⇒ 可测，召回 0）**是两件事**。
- `CitationVerdict` + `score_citations(cited, *, available, evidence)`：判据住一处。
  - `fabricated = cited − available` ⇒ **编造**（硬判据，点名）
  - `grounded = 1 − |fabricated|/|cited|`
  - `依据召回 = |cited ∩ evidence|/|evidence|`（端到端，**同时受检索+生成影响**）
  - `依据用上率`（纯生成侧）
  - 归因拆分：`evidence_not_provided = evidence − available`（检索）
    ／ `evidence_ignored = (evidence ∩ available) − cited`（生成）
- 第三个校准答案器 **`FabricatingAnswerer`**（`--answerer fabricator`）：
  证明"引用了没给它的来源"这条路径**真的会被抓到**。oracle/null 都碰不到它。
- `trace`：`generation` 事件 `citations` 变必填（值可为 `null`）；`verify_against`
  从 **`generation.citations − retrieval.kept` 对减**独立重算 `fabricated`；
  `explain` 多一段"### 引用"（编造点名 + 归因两行）。
- 旧格式报告 / 旧 trace **一律拒绝**（缺 `citation` / 缺 `citations` 键），
  `asuka/runs/answers|traces/` 全清重跑。

## 第六轮：Context 装配接上内核（C-1 / C-3 / C-4）

### 做了什么

**新建 `asuka/context.py`** —— 检索之后加一步**受预算约束的装配**，复用内核：

| 不变量 | 内容 | 内核落点 |
|---|---|---|
| **C-1** | `Chunk`(Knowledge) → `ContextItem`(Context) 显式转换 | `RetrievalPipeline.to_context_items()` |
| **C-3** | Token Budget 硬约束：装不下就丢 | `budget.allocate()` |
| **C-4** | 静默截断是 bug：每条被丢的都留 `(id, tokens, 原因)` | `DroppedItem` |
| **C-10** | 知识片必须带 citation | `ContextItem.__post_init__` |

动机：`top_k` 是**条数不是 token 数** ⇒ **按条数控制的检索器会静默撑爆请求**，
失败在**模型那一侧**（`CONTEXT_LENGTH_EXCEEDED`），评测这一侧一切正常。

**改动面**：`textutil.estimate_tokens` 改为**委托** `HeuristicTokenizer`（不再自己写）；
`answers.py` 全链路（`available` 用装配后的 id、三段归因、报告加 `## 上下文（Context）` 节、
三个 CLI 开关）；`trace.py`（retrieval 事件加 `context`/`dropped_budget`/`context_tokens`，
identity 加三个装配参数，`verify_against` 对账，explain 显示"模型没看见"标记）。

### 两条关键判据

1. **`retrieved` 与 `available` 是两个集合**。混成一个 ⇒ 被预算丢掉的片读成
   "模型见过它" ⇒ 编造读成有依据 ⇒ **分数只会变好看，没有任何东西会报错**。
   归因因此从两段变**三段**（互斥、恰好划分 evidence）：
   没检到（换检索器）/ 装不下（**加窗口**）/ 给了没引（改 prompt）。
2. **取舍顺序必须按相关性**。`allocate()` 的键 `(not pinned, -priority, key)`，
   而内核 `knowledge_chunk()` 的 `priority` 是**常数 30** ⇒ 退化成按 `chunk_id`
   **字母序**丢（丢第一名、留最后一名，**静默**）。
   ⇒ 装配时把**检索名次**写进 `priority`：**用**内核的旋钮，不是绕过它。

## 第七轮：回归对比接上 `agent_evaluation.regression`（"这次 vs 上次"）

### 做了什么

把 AgentOS 那边**从没人接上**的"这次 vs 上次"回归对比，接进 Asuka。新建
`asuka/regression.py`，**复用** `packages.agent_evaluation.regression` 的 `compare` /
`regressions` / `Delta`（规则不住在 Asuka 里），外面只加 Asuka 需要的两层：

- **可比性这道门**（`check_comparable`）：topic / retriever / answerer / top_k /
  samples_per_task / context_budget / reserved_for_output / chars_per_token /
  corpus_chunks / calibration + **逐题** question 文本与 points_total 条数。
  和 `compare.py` 同纪律：**不可比就拒绝、一次报全部原因、一个指标数字都不印**。
- **题级口径**：`AnswerScore.passed` 是一条样本；回归是一道题对一道题。
  **通过 = 这道题的全部采样都通过**（pass@1 == 1.0），印在报告第一段。
  不用"至少一次通过"（`3/3 → 1/3` 会被读成 unchanged）；本口径下**一次采样翻转就算回归**，
  所以报告**必须**同时印前后比例（判定给结论、比例给分辨力）。
- **不可测点名**：`points_total == 0` ⇒ `passed` 恒 False，直接比会以"两次都不通过"落进
  unchanged（读成"已知问题"，实为"压根没测"）。⇒ 排除 + 单独点名。
- **守死的语义**：`unchanged` 含"两次都不通过"（**backlog，不是回归**）；report 里 backlog
  单独成节、标题直接写"不是这次退步"。
- **CLI**：`asuka.regression <旧> <新> --out --json`。拒绝时退出码 2、stdout 空、但
  `--out/--json` **照写**（和 compare 不同：显式 flag 静默忽略 = 承诺未交付）；读不回报告
  退出码 3；`--allow-non-comparable` 只放行内容、退出码仍是 2。

### 实测（Redis 语料，同配置两次 `null` 跑，top_k=10）

`null` 全答空串 ⇒ 24 题两次都不通过：regressed **0** / improved 0 / unchanged 24（全是 backlog）/
new 0。《回归》节印「没有回归。」并紧跟「这句话不等于『一切都好』」。
对照：`oracle`(8192 窗口) vs `oracle`(400 窗口) **被拒绝**，理由 context_budget + reserved_for_output
两项不一致 —— 换窗口改的是"喂进 prompt 的那一份"，不是系统退步。

### ⚠️ 第一版结论是**假的**，被自己的匹配器骗了

严格子串匹配 ⇒ 77 条里 **66 条（85.7%）**判"语料缺口"。**高得可疑 ⇒ 先怀疑匹配器**：

⇒ **改双档匹配**：严格（词边界子串）+ 宽松（词干化 + 内容词同块）。
⇒ 又发现第三层混淆：宽松档要求同块，而 hard 题恰恰要**跨片综合**
（"选型：hash vs string"要对比两篇）⇒ 再拆"能否在不同片拼齐"。

### 结论（宽松档，77 条真丢要点）

| 类别 | 条数 | 占比 | 该动什么 |
|---|---|---|---|
| ① 依据里就有（同片）⇒ **纯生成侧** | 17 | 22.1% | 补文档**没用** |
| ② 语料里有、不在声明依据 ⇒ 标注/检索 | 12 | 15.6% | 修标注 / 检索 |
| ③a 材料在但**跨片**（可拼齐）⇒ 综合/检索 | 24 | 31.2% | 补文档**没用**（要的是综合） |
| ③b **真·材料缺失** | 24 | 31.2% | **补文档才有用** |

## M97：Task Factory 一对多（Fan-out，基线 §2.3 `Step : Task = 1 : N`）

起因：核实 Agent Runtime 六项时发现 **Task Factory 名不副实** ——
基线要求"一个 Step 可产生多个 Task"（支持 Parallel / Fan-out / Batch / DAG），
而代码只有 `from_action() -> Task`，loop 四处调用全是单条 `add_task`。

### 底层本来就能 1:N，缺的只是出口
- `Step.add_task()` / `derive_step_status()` / `Worker.run_once(limit=N)` 都支持多条；
  **唯一缺的是 `TaskFactory` 没有"一个 Action 多个 Task"的出口**。

### 做法
- `TaskFactory.from_actions(action) -> list[Task]`：扇出载体是
  `action.payload["tasks"]`（一个 `{tool, args}` 列表）。
  ⚠️ **刻意不新造 `ActionType.FAN_OUT`** —— 那会多一个"声明了却没人管"的枚举
  （M88/M90 的老毛病）。扇出是"同一 Action 多个分支"，不是新动作。
- 分支**属于同一个 Step**（`step_id` 同一个）—— 这正是 1:N 的落点。
  分支只覆盖 `tool`/`args`，`run_id`/`action_type`/`risk_level`/`timeout` 继承父 Action。
- `from_action()` 遇到扇出 Action **直接拒绝**（否则多出来的分支会被静默丢掉）。
- `loop._execute`：提交全部 Task、`run_once(limit=len(...))` 一次跑完、逐个
  `_observe` + `_record_compensation` + `_charge`。
  ⚠️ 用 `limit=1` 会把第 2..N 个 Task 留在 PENDING，Step.status 永远是 PENDING。

**新增**：`test_task_factory_fan_out.py`(6) + `test_agent_loop.py:FanOutTest`(3，含控制组)。
全量单测 **1839 全绿**。架构页「Task Factory」改回 ✅ 已落地。

## M101：M9 企业治理上半 —— Policy-as-Code（OPA 风格）+ Sandbox

用户从 M 层剩余里挑 **M9 Sandbox/OPA**（对"企业级"定位最实）。两者各补一个
"有枚举/有模块，但没人真的用得上"的洞。

### 空洞一：策略只能由 Python 构造（没有"策略即数据"）
`PolicyEngine(rules=(PolicyRule(...),))` —— 改一条策略 = 改代码 + 重新部署。
OPA 的做法是把策略变成**数据**，由独立决策点（PDP）加载评估；执行点（PEP，即
`Harness.before_action`）只问结果。

新增 `packages/agent_harness/policy_document.py`：`PolicyDocument.from_mapping()` →
严格校验 → `compile() -> PolicyEngine`。三条不变量：
- **P-1 未知 effect / 字段 / action_type 在加载期拒绝**，绝不静默忽略。
  一个拼错的 `effect:"audit"` 退化成默认放行是策略里最危险的一类 bug；
  `when.tool` 少写一个 `s`（正确 `tools`）不许退化成"没有约束"。
- **P-2 `default` 必须显式写下来**。省略 default = 悄悄把 fail-closed 变成 fail-open；
  "什么都没匹配时怎么办"是策略的性质，不是可以省的默认值。
- **P-3 决策点/执行点分离**：本模块只产出 `PolicyEngine`，不 import `Harness`、无副作用。
另给 `PolicyRule` 加 `attributes` 精确匹配（策略即数据要能表达"环境"，如 `{"env":"prod"}`）。

### 顺带抓到的真 bug（M101 直接战果）
`PolicyEngine.evaluate()` 走到默认分支时写 `PolicyDecision(verdict=default, reason="")`，
而 `PolicyDecision` 的 H-1 要求**非 ALLOW 必须带 reason** ⇒ `default_verdict=DENY`
**一走到默认分支就当场抛 InvariantViolation**。也就是说：一份 `default: deny`
的策略根本表达不出来（不是"默认拒绝不生效"，是"引擎崩"）。已修：默认拒绝的
reason 就是"没有任何规则命中"，写出来既满足 H-1，也让审计读得到原因。
（与 M99 的 `state_from_dict` 同族：新功能逼出一条一直潜伏的旧路。）

### 空洞二：`ToolProtocol.SANDBOX` 只是个"声明了却没人管"的枚举值
全仓 0 处真的隔离。新增 `packages/agent_runtime/tool_runtime/sandbox.py`。
**核心是"只声称守得住的东西"** —— 进程内 Python 关不住任意代码，
任何声称"能隔离文件系统/网络"的实现都是编（M88）：
- ✅ 真的强制：硬超时（到点 kill）、输出上限（**拒绝不截断**）、环境变量白名单、
  禁 shell 字符串（只收 argv 列表）、干净工作目录、声明路径校验（尽力而为的输入校验）。
- ❌ 刻意**不提供** `network_hosts` 这类旋钮：提供一个管不住的旋钮比不提供更糟
  —— 会让读代码的人以为网络被挡住了。文件系统/网络隔离需要 OS 级 namespace。
- **注册契约（收窄 T-6）**：`protocol=SANDBOX` 的工具，Invoker **必须**是
  `SandboxedInvoker`（`registry.register` 点名拒绝）。声明了沙箱却跑在裸函数里 = 谎话。
  `SandboxViolation` 由 `ToolRuntime.call` 翻成带 code 的 `ToolExecutionError`。

## M103：M4 连接上半 —— JSON-RPC 2.0 核心 + MCP 客户端/Invoker

用户接着挑 **M4 MCP/A2A**。M4 的 Multi-Agent（子 Run）早就落地，
缺的是 MCP / A2A —— 全仓只出现在注释里（`ToolProtocol.MCP`、
`ToolRegistry` 的"真实实现换成 MCP"）。这轮先做 **MCP**，把 A2A 留成下一半。

### 为什么先有 `jsonrpc.py` 这一层
MCP 与 A2A 底下是同一个东西：JSON-RPC 2.0。各写一份，分岔点恰好是**错误路径**。
所以先落一层与协议无关的核心，三条不变量：
- **J-1** 对端必须说 `jsonrpc:"2.0"`；
- **J-2** 响应必须是 `result` / `error` **恰好其一**，且 error 形状（int code + str message）不对即拒；
- **J-3** `id` 必须与请求相等 —— 不等说明响应串了线，**把别人的结果当成自己的**比报错危险。

### Transport：request 与 send **必须分开**（当场踩到的坑）
`StdioTransport` 第一版让 `notify` 也走 `request`，而 `request` 是"写一行再读一行"。
服务端按协议**不回答通知** ⇒ `readline()` **永久阻塞** ⇒ 测试挂死（不是失败，是死锁）。
修法：Transport 协议加 `send`（只写不读），`JsonRpcClient.notify` 走 `send`。
`StdioTransport` 用换行分隔 JSON over stdin/stdout（MCP 的 stdio 形态），
`close()` 必须 terminate 后 wait（REFERENCE 第 41 条）。

### MCP
- `McpClient`：`initialize`（+ 发 `notifications/initialized`，漏发会让服务端
  "说不认识工具"，症状指向工具名而非初始化）/ `list_tools` / `call_tool`
  （幂等键走 `_meta`，§16）。
- `McpInvoker`（`ToolInvoker`）：把 `ToolCall` 翻成 `tools/call`；
  **`isError` 必须翻成异常**——否则一次失败的工具调用被读成"成功，结果里有个 isError 字段"。
- `register_mcp_tools`：发现并登记进 `ToolRegistry`（`protocol=MCP`），支持 `prefix` 消歧。
- **MC-1** 无名字/重名的 MCP 工具拒绝登记（没有名字无法寻址）。
- **MC-2** `side_effect` **不猜**：只有服务端声明 `annotations.readOnlyHint=true` 才是
  `READ`，其余一律 `UNKNOWN` ⇒ T-2 会要求幂等键（防重复副作用）。

## M104：M4 连接下半 —— A2A 客户端 + 远端委派 Spawner

用户接着收 M4。M4 的 Multi-Agent 只限**同进程**（`InProcessChildRunSpawner`），

### `packages/agent_runtime/connectivity/a2a.py`
- `AgentCard`（name/url/capabilities/skills，抽我们真用得到的字段）+ `AgentCardTransport`
  （`InMemoryCardTransport` / `HttpCardTransport` 用 stdlib urllib）——Agent Card 是
  **普通 HTTP GET**，不是 JSON-RPC，所以走单独的 transport（不假装一条 RPC 就能拿卡）。
- `A2AClient`：`message/send`（带 `contextId=parent_run_id` 让远端能关联）、
  `tasks/get`、`tasks/cancel`。
- `A2AChildRunSpawner`（实现 `ChildRunSpawner`）：`spawn` 发消息并把远端 Task 的 id
  当 `child_run_id` 登记（**D-1 去重照旧**）；`poll` 是远端→本地的结算通道，
  终态才 `mark_finished`；`cancel_child` 发 `tasks/cancel`。接进
  `assemble_runtime_stack(spawner=...)` 即走 Loop 既有的 `_suspend_for_child`。

### 三条不变量 + 一个实证的坑
- **A-1** 只有终态才写终态（`working`/`submitted` 不许被记成 completed/failed）。
- **A-2** `input-required`/`auth-required` **既非终态亦非失败**（当失败会把
  "需要人补一句话"变成一次静默委派失败，D-10 同款）。
- **A-3** A2A 状态是**闭集**，未知字符串拒绝（兜底成 working 会把真终态读成还在跑）。
- ⚠️ **拼写坑**：A2A 用美式 `canceled`，AgentOS 唤醒路径认英式 `cancelled`
  （`child_wake` 的 `handle.status == "cancelled"`）。不归一化 ⇒ 远端取消被读成
  **失败**。`_A2A_TO_AGENTOS_STATUS` 里显式映射，测试钉住。
- ⚠️ 同步完成的远端：`spawn` 要把结果落登记处，但**返回未终态的 handle** ——
  否则 Loop 拿着它撞 D-11（挂起去等一个不会再变的答案）。返回 `bind()` 的原始快照，
  唤醒扫照样看得到结果。
